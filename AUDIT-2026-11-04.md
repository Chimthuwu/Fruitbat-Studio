# Lemon Studio code audit — 2026-11-04 (4 parallel audits, file:line evidence)

## 1. os-app / os-ui / os-theme (UI) — YES
- Full Project clones on UI thread per tick during drags (app.rs:4219, rack.rs:2653, transport.rs:671-686)
- All-CPU rendering (tiny-skia+softbuffer), per-frame allocs in resampling (os-ui/lib.rs:1105); 4K ceiling
- Hard-coded 1920x1080 layout, min 1024x600 "below this they break" (main.rs:709)
- God-functions: mouse_move ~600L, act ~450L (app.rs:5675/8468); no component layer
- GDI text engine copies+hashes bg pixels per string per frame (text.rs:374-420)
- Fire-and-forget mpsc UI->audio, no backpressure; ~2,036 unwrap/expect sites
Verdict: remarkably disciplined pre-alpha; weaknesses are scale/responsiveness, not correctness.

## 2. os-engine / os-dsp — CONDITIONALLY
Critical:
- Sinc recompute per tap per sample, ~81 transcendentals/frame/voice, zero SIMD (engine.rs:4020-4091)
- Audio-thread work spikes: metronome click synth+alloc (metronome.rs:258), LIN-EQ full-history replay w/ 8 FFTs in one frame N<=65536 (eq/lin.rs:285), synchronous time-stretch on first note (engine.rs:3975), per-block Vec allocs (love_philter/mod.rs:1214, maximus/mod.rs:1198, chain.rs:78)
- unsafe multicore: raw-pointer Sync, graph-based correctness unverified (multicore.rs:99-150); blocking Mutex::lock at engine.rs:3510
- Crash paths: formula parser unbounded recursion -> stack overflow (formula.rs:601); pdc.rs:383 zero-port panic; reverb.rs:213 unbounded predelay alloc
Major: maximus 2xHIGH sum when mid off (1173-1190); SVF coefficient=1.0 instability (filter.rs:83); try_lock bypass -> clicks (chain.rs:189-201); unbounded memory (sample.rs:823, notes.rs:496); O(n) voice scans; zipper noise EQ automation; naive FIR in maximus; vocoder 100 bands per sample.
Verdict: adopt os-dsp + effects crates; engine core needs RT-hardening pass before carrying a product.

## 3. os-project / os-smf — YES (with fixes)
- ANSI decoded as Latin-1, chars >=U+0100 rewritten to '?' on save -> permanent corruption (project.rs:233-256)
- patch_bytes silently no-ops on short records -> edits silently lost on save (project.rs:2433-2441; call sites 3302-3335, 2237, 3801)
- os-smf lossy: sysex/unknown meta/system-common dropped, Ok returned; format-0 validation missing; TimeSig denominator corruption; corrupt files read as empty Ok
Verdict: container/event layer excellent (byte-exact round-trip, offset errors, corpus tests); fix silent-failure write pattern + text encoding; split 7,098-line project.rs.

## 4. Plugin hosting + own plugins — YES (with fixes)
Critical/High:
- os-vst2 host callback trusts plugin-controlled host_reserved_2 pointer (host.rs:141-145)
- os-vst2 save_state trusts chunk ptr/size, OOB read (lib.rs:887); enumeration + first instance creation unguarded (lib.rs:119-131, 270, 302)
- os-clap queues push past reserved capacities -> malloc in process() (lib.rs:957-963, 1551-1743)
- os-vst3 unreserved Vecs in process_chunk (lib.rs:1188-1251); context_menu parser panics on malformed plugin data (context_menu.rs:234)
- Medium: VST3 try_lock priority inversion; flush() UI-thread 0-sample process sharing state; citrus render-path unwraps, feed.clone(), no denormal flush.
Verdict: crash-guard architecture (SEH trampolines + fault-injection tests) is rare and hard to retrofit. Cheap fixes: queue capacity guards, pre-reserve VST3 Vecs, harden VST2 pointer paths, guard enumeration.

## OVERALL
Worth building on as a foundation, not turnkey. Strongest: os-project lossless core, os-dsp/effects, crash containment, test culture. Before product work on the engine: RT-thread discipline, unsafe multicore validation, SIMD/resampler table, data-integrity fixes (text encoding, silent patches), containment holes.
